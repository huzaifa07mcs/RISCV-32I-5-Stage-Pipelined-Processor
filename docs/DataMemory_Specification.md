# DataMemory Specification

## 1. Module Name
`DataMemory`

---

## 2. Purpose

The Data Memory module stores and provides access to data used by load (`LW`) and store (`SW`) instructions.

It supports:

- **Synchronous write** (on the rising edge of the clock, controlled by `write_enable`)
- **Combinational read** (read data is available immediately after the address changes)

A combinational read is required for a **single-cycle processor** because the data loaded by an `LW` instruction must be available within the same clock cycle so it can pass through the write-back mux and be written into the register file before the next rising clock edge.

The module treats the input address as a **word index** into the memory array. Since the memory depth is 256 words, only the lower 8 bits (`address[7:0]`) are used to index the memory.

No byte-to-word address conversion is performed inside this module because this project uses a **word-addressable** memory model.

---

## 3. Inputs

| Signal | Width | Description |
|---------|------:|-------------|
| `clk` | 1 | System clock used for synchronous write |
| `address` | 32 | Memory address input (only `address[7:0]` is used as the word index) |
| `write_data` | 32 | Data to be written into memory |
| `write_enable` | 1 | Enables memory write (`MemWrite` from Main Control) |

---

## 4. Outputs

| Signal | Width | Description |
|---------|------:|-------------|
| `read_data` | 32 | Combinational read output from the selected memory location |

---

## 5. Parameters

| Parameter | Value | Description |
|-----------|------:|-------------|
| `XLEN` | 32 | Processor data width |
| `DEPTH` | 256 | Number of 32-bit words in memory |

---

## 6. Internal Storage

The memory is implemented as an array of 256 words.

```verilog
reg [XLEN-1:0] mem [0:DEPTH-1];
```

This is the first stateful module in the processor. Previous modules (ALU, ALU Control, Main Control, Immediate Generator) were purely combinational.

---

## 7. Memory Initialization

For simulation, all memory locations are initialized to zero using an `initial` block.

```verilog
integer i;

initial begin
    for (i = 0; i < DEPTH; i = i + 1)
        mem[i] = 0;
end
```

This prevents unknown (`X`) values during simulation and makes functional verification easier.

> **Note:** In real hardware, memory initialization depends on the target technology (ASIC SRAM, FPGA Block RAM, external memory, etc.) and is not generally guaranteed unless explicitly initialized.

---

## 8. Functional Behavior

### Write Operation (Synchronous)

The ALU provides a **byte address**. Since each memory location stores one 32-bit word (4 bytes), the two least significant address bits (`address[1:0]`) are ignored, and `address[9:2]` is used as the word index.

Memory is written only on the rising edge of the clock when `write_enable` is asserted.

```verilog
always @(posedge clk) begin
    if (write_enable)
        mem[address[9:2]] <= write_data;
end
```

---

### Read Operation (Combinational)

The selected memory location is continuously available on the output.

```verilog
assign read_data = mem[address[9:2]];
```

---

### Design Notes

- The ALU generates a **byte address** for load (`LW`) and store (`SW`) instructions.
- Since each memory location stores a 32-bit word, the two least significant address bits are ignored when indexing the memory array.
- Writes occur only on the rising edge of the clock.
- Reads are asynchronous (combinational).
- A combinational read is required in the single-cycle processor so that an `LW` instruction can complete within one clock cycle.
- A synchronous read would delay the loaded data by one clock cycle, making it unsuitable for the single-cycle datapath.



## 9. Reset Behavior

The Data Memory module does **not** include a reset input.

Memory contents remain unchanged until modified by a valid store (`SW`) operation.

For simulation, the initial memory contents are defined by the initialization block described in Section 7.

---

## 10. Verification

The following functionality is verified using a self-checking Verilog testbench.

### Test Cases

- Write data to a memory location and read it back.
- Overwrite an existing memory location and verify the updated value.
- Write to one address and verify another address is unaffected.
- Verify that memory is not modified when `write_enable = 0`.
- Read an unwritten memory location (returns the initialized value of `0`).
- Verify correct operation at boundary addresses (`0` and `255`).
- Perform multiple sequential writes and verify each stored value independently.

---

## 11. Design Notes

- This is the first sequential (stateful) module in the processor.
- Memory writes are controlled directly by the `MemWrite` signal generated by the Main Control Unit.
- The same Data Memory module will be reused in the pipelined processor without modification.
- In the pipelined processor, the module is placed in the **MEM** stage, while pipeline registers before and after the memory provide the required timing separation.
- The module assumes a **word-addressable** memory model throughout the project.
