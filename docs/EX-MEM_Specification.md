# EX/MEM Pipeline Register Specification

## 1. Module Name
`EX_MEM`

## 2. Purpose

The EX/MEM Pipeline Register separates the **Execute (EX)** stage from the **Memory Access (MEM)** stage in the pipelined RV32I processor. It captures all outputs generated by the Execute stage on every rising edge of the clock and forwards them to the Memory stage during the next clock cycle.

This register stores both the data generated by the Execute stage and the associated control signals so that the Memory and Write-Back stages operate on the same instruction. It stores the ALU result, data to be written into memory, destination register information, PC+4 (for JAL write-back), and the control signals required by the MEM and WB stages.

**Design Note:** Branch resolution (`Zero` flag evaluation, branch decision, and pipeline flush generation) is completed combinationally inside the Execute stage before this pipeline register. Therefore, neither the `Zero` flag nor the branch target address is stored in the EX/MEM register. This keeps the branch penalty limited to two cycles.

**Design Note (MemRead):** This design does not use a dedicated `MemRead` control signal, since `DataMemory`'s read is combinational and always active (no read-enable input exists). For load-use hazard detection in the upcoming Hazard Detection Unit, `MemToReg` is reused as the "this instruction is a load" flag instead of introducing a separate `MemRead` signal — in this design's control scheme, `MemToReg=1` uniquely identifies LW, since no other supported instruction sets it.

## 3. Inputs

| Signal | Width | Description |
|---------|:----:|-------------|
| clk | 1 | System clock |
| reset | 1 | Active-high synchronous reset |
| flush | 1 | Flushes the pipeline register |
| alu_result_in | 32 | ALU computation result |
| rs2_data_in | 32 | Register data to be written into Data Memory (SW) |
| rd_in | 5 | Destination register address |
| pc_plus4_in | 32 | PC+4 carried through the pipeline so the WB stage can write the return address during JAL execution |
| Jump_in | 1 | Jump control signal for JAL write-back |
| MemWrite_in | 1 | Enables Data Memory write |
| RegWrite_in | 1 | Enables Register File write |
| MemToReg_in | 1 | Selects Memory data or ALU result during write-back (also doubles as the load-instruction flag for hazard detection — see Design Note above) |

## 4. Outputs

| Signal | Width | Description |
|---------|:----:|-------------|
| alu_result_out | 32 | Registered ALU result |
| rs2_data_out | 32 | Registered store data |
| rd_out | 5 | Registered destination register |
| pc_plus4_out | 32 | Registered PC+4 for JAL write-back |
| Jump_out | 1 | Registered Jump control |
| MemWrite_out | 1 | Registered Memory Write control |
| RegWrite_out | 1 | Registered Register Write control |
| MemToReg_out | 1 | Registered Memory-to-Register control |

## 5. Functional Behavior

### Normal Operation

When `reset` and `flush` are deasserted, the EX/MEM pipeline register captures all Execute stage outputs on every rising edge of the clock.

```verilog
alu_result_out <= alu_result_in;
rs2_data_out   <= rs2_data_in;
rd_out         <= rd_in;
pc_plus4_out   <= pc_plus4_in;
Jump_out       <= Jump_in;
MemWrite_out   <= MemWrite_in;
RegWrite_out   <= RegWrite_in;
MemToReg_out   <= MemToReg_in;
```

### Reset Operation

When `reset` is asserted, all outputs are cleared.

```verilog
alu_result_out <= 32'b0;
rs2_data_out   <= 32'b0;
rd_out         <= 5'b0;
pc_plus4_out   <= 32'b0;
Jump_out       <= 1'b0;
MemWrite_out   <= 1'b0;
RegWrite_out   <= 1'b0;
MemToReg_out   <= 1'b0;
```

Reset inserts a **NOP** into the Memory stage.

### Flush Operation

When `flush` is asserted, the pipeline register is cleared to insert a bubble into the pipeline.

Although clearing only the control signals is sufficient, clearing all stored data keeps the register contents clean and simplifies debugging.

```verilog
alu_result_out <= 32'b0;
rs2_data_out   <= 32'b0;
rd_out         <= 5'b0;
pc_plus4_out   <= 32'b0;
Jump_out       <= 1'b0;
MemWrite_out   <= 1'b0;
RegWrite_out   <= 1'b0;
MemToReg_out   <= 1'b0;
```

## 6. Priority

When multiple control conditions occur simultaneously, the following priority shall be used:

1. Reset
2. Flush
3. Normal Update

```verilog
always @(posedge clk)
begin
    if (reset)
    begin
        ...
    end
    else if (flush)
    begin
        ...
    end
    else
    begin
        ...
    end
end
```

## 7. Hardware Resources

This module consists only of pipeline registers. No combinational logic, arithmetic, logical, or memory operation is performed inside this module. It simply delays the Execute stage outputs by one clock cycle before forwarding them to the Memory stage.

Stored signals:

- ALU result
- rs2 register data (store data)
- Destination register (rd)
- PC+4 (JAL return address)
- Control signals:
  - Jump
  - MemWrite
  - RegWrite
  - MemToReg

## 8. Reset Behavior

Active-high synchronous reset.

After reset:

- ALU result = 0
- Store data = 0
- Destination register = 0
- PC+4 = 0
- Jump = 0
- MemWrite = 0
- RegWrite = 0
- MemToReg = 0

The Memory stage receives a NOP.

## 9. Verification Strategy

The module should be verified using a dedicated testbench covering:

- Reset operation
- Normal pipeline update
- ALU result transfer
- Store data transfer
- Destination register transfer
- PC+4 transfer (verify JAL return address propagation)
- Control signal transfer
- Flush operation
- Multiple consecutive instruction transfers
- Back-to-back instruction transfers without data corruption

| Test Case | Expected Result |
|-----------|-----------------|
| Normal clock | Inputs appear at outputs |
| Reset | All outputs become zero |
| Flush | All outputs become zero |
| JAL instruction | PC+4 and Jump correctly transferred |
| Multiple instructions | Correct sequential transfer |
| Consecutive instructions | No corruption between adjacent instructions |

## 10. Notes

- This module forms the pipeline boundary between the **Execute (EX)** and **Memory Access (MEM)** stages.
- It delays all required data and control signals by one clock cycle.
- No ALU operation occurs inside this module.
- No Data Memory operation occurs inside this module.
- `branch_target` and `Zero` are deliberately **not** stored because branch resolution is completed combinationally in the Execute stage before this register.
- `rs2_data` is carried separately because the ALU computes the memory address, while the original `rs2` value is required as the data written into Data Memory during `SW` instructions.
- `pc_plus4` and `Jump` are propagated only to support correct JAL write-back in the WB stage.
- No dedicated `MemRead` signal exists in this design; `MemToReg` serves double duty as the load-instruction flag consumed by the Hazard Detection Unit.
- This module contains no combinational logic; it only registers signals between pipeline stages.
