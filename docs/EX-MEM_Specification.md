# EX/MEM Pipeline Register Specification

## 1. Module Name

`EX_MEM`

---

## 2. Purpose

The EX/MEM Pipeline Register separates the **Execute (EX)** stage from the **Memory Access (MEM)** stage in the pipelined RV32I processor.

It captures all outputs generated by the Execute stage on every rising edge of the clock and forwards them to the Memory stage during the next clock cycle.

This register stores the ALU result, branch information, data to be written into memory, destination register information, and the control signals required by the MEM and WB stages.

---

## 3. Inputs

| Signal | Width | Description |
|---------|:----:|-------------|
| clk | 1 | System clock |
| reset | 1 | Active-high synchronous reset |
| flush | 1 | Clears pipeline register when asserted |
| branch_target_in | 32 | Calculated branch target address |
| zero_in | 1 | Zero flag generated by ALU |
| alu_result_in | 32 | ALU computation result |
| rs2_data_in | 32 | Register data to be written into Data Memory (SW) |
| rd_in | 5 | Destination register address |
| Branch_in | 1 | Branch control signal |
| MemRead_in | 1 | Enables memory read |
| MemWrite_in | 1 | Enables memory write |
| RegWrite_in | 1 | Enables register file write |
| MemToReg_in | 1 | Selects memory data or ALU result for write-back |

---

## 4. Outputs

| Signal | Width | Description |
|---------|:----:|-------------|
| branch_target_out | 32 | Registered branch target address |
| zero_out | 1 | Registered ALU zero flag |
| alu_result_out | 32 | Registered ALU result |
| rs2_data_out | 32 | Registered data for Data Memory write |
| rd_out | 5 | Registered destination register |
| Branch_out | 1 | Registered branch control |
| MemRead_out | 1 | Registered memory read control |
| MemWrite_out | 1 | Registered memory write control |
| RegWrite_out | 1 | Registered register write control |
| MemToReg_out | 1 | Registered memory-to-register control |

---

# 5. Functional Behavior

## Normal Operation

When `reset` and `flush` are not asserted, the EX/MEM pipeline register captures all Execute stage outputs on every rising edge of the clock.

```verilog
branch_target_out <= branch_target_in;
zero_out <= zero_in;

alu_result_out <= alu_result_in;
rs2_data_out <= rs2_data_in;

rd_out <= rd_in;

Branch_out <= Branch_in;
MemRead_out <= MemRead_in;
MemWrite_out <= MemWrite_in;
RegWrite_out <= RegWrite_in;
MemToReg_out <= MemToReg_in;
```

---

## Reset Operation

When `reset` is asserted, all pipeline register outputs are cleared.

```verilog
branch_target_out <= 32'b0;
zero_out <= 1'b0;

alu_result_out <= 32'b0;
rs2_data_out <= 32'b0;

rd_out <= 5'b0;

Branch_out <= 1'b0;
MemRead_out <= 1'b0;
MemWrite_out <= 1'b0;
RegWrite_out <= 1'b0;
MemToReg_out <= 1'b0;
```

Reset inserts a NOP into the Memory stage.

---

## Flush Operation

When `flush` is asserted, the pipeline register is cleared.

This is used to invalidate instructions that should not proceed to the Memory stage.

```verilog
Branch_out <= 1'b0;
MemRead_out <= 1'b0;
MemWrite_out <= 1'b0;
RegWrite_out <= 1'b0;
MemToReg_out <= 1'b0;
```

No memory access or register write occurs for the flushed instruction.

---

# 6. Priority

When multiple control signals occur simultaneously, the priority shall be:

1. Reset
2. Flush
3. Normal Update

Example implementation:

```verilog
always @(posedge clk)
begin

    if(reset)
    begin
        ...
    end

    else if(flush)
    begin
        ...
    end

    else
    begin
        ...
    end

end
```

---

# 7. Hardware Resources

This module consists only of pipeline registers.

Stored signals:

## Execute Results

- Branch target address
- ALU Zero flag
- ALU result

## Register Data

- rs2 register data (store data)

## Destination Register

- rd address

## Control Signals

- Branch
- MemRead
- MemWrite
- RegWrite
- MemToReg

No arithmetic, logical, or memory operation is performed inside this module.

---

# 8. Reset Behavior

Active-high synchronous reset.

After reset:

- Branch target output = 0
- Zero flag = 0
- ALU result = 0
- Store data = 0
- Destination register = 0
- All control signals = 0

The pipeline contains an empty instruction (NOP).

---

# 9. Verification Strategy

The module should be verified using a dedicated testbench covering:

- Reset operation
- Normal pipeline update
- ALU result transfer
- Branch target transfer
- Zero flag transfer
- Store data transfer
- Destination register transfer
- Control signal transfer
- Flush operation
- Multiple consecutive instruction transfers

Expected behavior:

| Test Case | Expected Result |
|-----------|-----------------|
| Normal clock | Inputs appear at outputs |
| Reset | All outputs become zero |
| Flush | All control signals become zero |
| Multiple instructions | Correct sequential transfer |

---

# 10. Notes

- This module creates the third pipeline boundary of the processor.
- No ALU operation occurs inside this module.
- No Data Memory operation occurs inside this module.
- The ALU result generated in the Execute stage is stored and forwarded to the Memory stage.
- The `rs2_data` signal is used only by store (`SW`) instructions.
- The `zero` flag and `branch_target` are used for branch decision logic.
- The outputs represent the complete execution state transferred from the Execute stage to the Memory stage.
