# ID/EX Pipeline Register Specification

## 1. Module Name

`ID_EX`

## 2. Purpose

The ID/EX Pipeline Register separates the **Instruction Decode (ID)** stage from the **Execute (EX)** stage in the pipelined RV32I processor.

It captures decoded instruction information, register values, immediate values, instruction fields, and control signals generated during the ID stage on every rising clock edge.

The stored values are forwarded to the EX stage during the next clock cycle, allowing the ID and EX stages to operate simultaneously while maintaining correct instruction execution.

The `ID_EX` register forwards `ALUOp` instead of the final `ALUControl`.

`ALU_Control` is generated in the EX stage using:

- `ALUOp_out`
- `funct3_out`
- `funct7_5_out`

This keeps ALU decision logic close to the ALU, following the standard pipelined processor design approach.

# 5. Functional Behavior

The ID/EX pipeline register stores all decoded information from the ID stage and transfers it to the EX stage on the next clock cycle.

## Normal Operation

During normal operation, all input signals are transferred to the corresponding outputs.

```verilog
pc_out <= pc_in;
pc_plus4_out <= pc_plus4_in;
rs1_data_out <= rs1_data_in;
rs2_data_out <= rs2_data_in;
imm_out <= imm_in;

rs1_out <= rs1_in;
rs2_out <= rs2_in;
rd_out <= rd_in;

funct3_out <= funct3_in;
funct7_5_out <= funct7_5_in;

ALUSrc_out <= ALUSrc_in;
ALUOp_out <= ALUOp_in;
Branch_out <= Branch_in;
Jump_out <= Jump_in;
MemWrite_out <= MemWrite_in;
RegWrite_out <= RegWrite_in;
MemToReg_out <= MemToReg_in;
```

---

# 6. Reset Operation

The reset input is an active-high synchronous reset.

When reset is asserted, all outputs are cleared and the pipeline receives a NOP instruction.

```verilog
pc_out <= 32'b0;
pc_plus4_out <= 32'b0;
rs1_data_out <= 32'b0;
rs2_data_out <= 32'b0;
imm_out <= 32'b0;

rs1_out <= 5'b0;
rs2_out <= 5'b0;
rd_out <= 5'b0;

funct3_out <= 3'b0;
funct7_5_out <= 1'b0;

ALUSrc_out <= 1'b0;
ALUOp_out <= 2'b0;
Branch_out <= 1'b0;
Jump_out <= 1'b0;
MemWrite_out <= 1'b0;
RegWrite_out <= 1'b0;
MemToReg_out <= 1'b0;
```

---

# 7. Flush Operation

Flush is used to handle control hazards caused by taken branches and jumps.

When flush is asserted, the current instruction in the pipeline is converted into a NOP by disabling all control signals.

```verilog
ALUSrc_out <= 1'b0;
ALUOp_out <= 2'b0;
Branch_out <= 1'b0;
Jump_out <= 1'b0;
MemWrite_out <= 1'b0;
RegWrite_out <= 1'b0;
MemToReg_out <= 1'b0;
```

---

# 8. Priority

The ID/EX pipeline register follows this priority order:

1. Reset
2. Flush
3. Normal Update

```verilog
always @(posedge clk)
begin
    if(reset)
        reset_values;
    else if(flush)
        flush_values;
    else
        transfer_inputs;
end
```

# 9. Hardware Resources

The ID/EX module contains only pipeline registers.

No:

- Arithmetic operation
- Logical operation
- Memory access

is performed inside this module.

Stored signals:

- PC
- PC + 4
- rs1 data
- rs2 data
- Immediate value
- rs1, rs2, rd addresses
- funct3
- funct7[5]
- ALUSrc
- ALUOp
- Branch control
- Jump control
- Memory write control
- Register write control
- Memory-to-register control

---

# 10. Reset Behavior

After reset:

- All outputs become zero.
- All control signals are disabled.
- The Execute stage receives a NOP instruction.

This prevents invalid instructions from being executed after reset.

# 12. Notes

- This is the second pipeline boundary of the processor.
- `ALUOp` is generated in the Decode stage and forwarded through this register.
- `ALU_Control` is generated in the Execute stage using `ALUOp_out`, `funct3_out`, and `funct7_5_out`.
- Only `funct7[5]` is stored because RV32I ALU operation selection requires this bit.
- `MemRead` is not used because this processor design does not require a separate memory read control signal.
- Flush disables all control signals to prevent incorrect instruction execution after control hazards.
