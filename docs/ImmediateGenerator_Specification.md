# Immediate Generator Specification

## 1. Module Name
ImmGen

## 2. Purpose
The Immediate Generator extracts the immediate value embedded in the 32-bit instruction and produces a sign-extended 32-bit output. Since RISC-V immediate bits are scattered across different positions depending on the instruction format (I, S, B, J), this module selects the correct bit-field arrangement based on a format-select control signal and sign-extends the result to XLEN width.

## 3. Inputs

| Signal | Width | Description |
|---|---|---|
| instruction | 32-bit | Full instruction fetched from Instruction Memory |
| ImmSrc | 2-bit | Format select: 00 = I-type, 01 = S-type, 10 = B-type, 11 = J-type |

## 4. Outputs

| Signal | Width | Description |
|---|---|---|
| imm_out | 32-bit | Sign-extended immediate value |

## 5. Parameters

| Parameter | Value | Description |
|---|---|---|
| XLEN | 32 | Processor data width |

## 6. Internal Storage
Not applicable — ImmGen is purely combinational logic, no storage elements.

## 7. Initialization
Not applicable — no memory or registers to initialize.

## 8. Functional Behavior
Combinational (`always @(*)` or `assign`), based on `ImmSrc`:

```verilog
// I-type (ImmSrc = 00):
imm_out = { {20{instruction[31]}}, instruction[31:20] };

// S-type (ImmSrc = 01):
imm_out = { {20{instruction[31]}}, instruction[31:25], instruction[11:7] };

// B-type (ImmSrc = 10):
imm_out = { {19{instruction[31]}}, instruction[31], instruction[7],
            instruction[30:25], instruction[11:8], 1'b0 };

// J-type (ImmSrc = 11):
imm_out = { {11{instruction[31]}}, instruction[31], instruction[19:12],
            instruction[20], instruction[30:21], 1'b0 };

// default:
imm_out = 32'b0;
```

Sign bit (`instruction[31]`) is always the topmost bit of the instruction, and is common across all formats — it is replicated to fill the upper bits so the extracted value's sign is preserved when widened to 32 bits.

B-type and J-type immediates are always even (bit[0] = 0), since branch and jump targets are byte-addressed but instructions are 2-byte aligned at minimum — the LSB is hardcoded to `1'b0` rather than extracted from the instruction.

## 9. Reset Behavior
ImmGen has no reset. It is a purely combinational module — output updates immediately whenever `instruction` or `ImmSrc` changes, with no dependency on clock or reset.

## 10. Verification
The following test cases shall be verified:
- I-type positive immediate (e.g., ADDI with small positive value) — confirm correct zero-upper-bits extension.
- I-type negative immediate (e.g., ADDI with negative value) — confirm correct sign-extension (upper bits = 1).
- S-type immediate (SW) — confirm correct reassembly of `imm[11:5]` and `imm[4:0]` from split instruction fields.
- B-type immediate (BEQ/BNE) with positive offset — confirm bit reordering and `imm[0] = 0`.
- B-type immediate with negative offset — confirm sign-extension from `instruction[31]`.
- J-type immediate (JAL) with positive offset — confirm correct bit reassembly across scattered fields.
- J-type immediate with negative offset — confirm sign-extension.
- Invalid/undefined `ImmSrc` value — confirm output defaults to a known safe value (0) rather than unknown/latch behavior.

## 11. Notes
- This module is purely combinational — critical for single-cycle timing since the immediate must be available in the same cycle as decode, alongside RegisterFile reads.
- `ImmSrc` will be generated by the Main Control Unit based on the instruction's opcode field.
- Reused without modification in the pipelined processor — sits in the ID stage, and its output (`imm_out`) is passed into the ID/EX pipeline register.
- Bit-field reordering for B-type and J-type reflects RISC-V's encoding optimization, where register fields (`rs1`, `rs2`, `rd`) stay in fixed positions across all instruction formats to simplify decode hardware — at the cost of scrambling immediate bits.
