# MEM/WB Pipeline Register Specification

## 1. Module Name
`MEM_WB`

## 2. Purpose

The MEM/WB Pipeline Register separates the **Memory Access (MEM)** stage from the **Write-Back (WB)** stage in the pipelined RV32I processor. It captures all outputs generated by the Memory stage on every rising edge of the clock and forwards them to the Write-Back stage during the next clock cycle.

This register carries forward everything the WB stage needs to compute the final write-back value and commit it to the Register File: the ALU result, the value read from Data Memory, the destination register address, PC+4 (for JAL), and the control signals `RegWrite`, `MemToReg`, and `Jump`.

This is the final pipeline register in the datapath — its outputs feed directly into the WB-stage write-back muxes (Mux A: `MemToReg` selecting ALU result vs. Data Memory read data; Mux B: `Jump` overriding with PC+4) and into the Register File's write port.

## 3. Inputs

| Signal | Width | Description |
|---------|:----:|-------------|
| clk | 1 | System clock |
| reset | 1 | Active-high synchronous reset |
| flush | 1 | Clears pipeline register when asserted |
| alu_result_in | 32 | ALU result, forwarded from EX/MEM |
| mem_read_data_in | 32 | Data read from Data Memory (valid for LW) |
| rd_in | 5 | Destination register address |
| pc_plus4_in | 32 | PC+4, needed for JAL write-back value |
| Jump_in | 1 | Jump control signal — selects PC+4 as write-back value |
| RegWrite_in | 1 | Enables Register File write |
| MemToReg_in | 1 | Selects Data Memory read data vs. ALU result for write-back |

## 4. Outputs

| Signal | Width | Description |
|---------|:----:|-------------|
| alu_result_out | 32 | Registered ALU result |
| mem_read_data_out | 32 | Registered Data Memory read data |
| rd_out | 5 | Registered destination register address |
| pc_plus4_out | 32 | Registered PC+4 for JAL write-back |
| Jump_out | 1 | Registered Jump control |
| RegWrite_out | 1 | Registered Register Write control |
| MemToReg_out | 1 | Registered Memory-to-Register control |

## 5. Functional Behavior

### Normal Operation

When `reset` and `flush` are deasserted, the MEM/WB pipeline register captures all Memory stage outputs on every rising edge of the clock.

```verilog
alu_result_out    <= alu_result_in;
mem_read_data_out <= mem_read_data_in;
rd_out            <= rd_in;
pc_plus4_out      <= pc_plus4_in;
Jump_out          <= Jump_in;
RegWrite_out      <= RegWrite_in;
MemToReg_out      <= MemToReg_in;
```

### Reset Operation

When `reset` is asserted, all outputs are cleared.

```verilog
alu_result_out    <= 32'b0;
mem_read_data_out <= 32'b0;
rd_out            <= 5'b0;
pc_plus4_out      <= 32'b0;
Jump_out          <= 1'b0;
RegWrite_out      <= 1'b0;
MemToReg_out      <= 1'b0;
```

Reset inserts a **NOP** into the Write-Back stage.

### Flush Operation

Although flushing this far down the pipeline is rare in a predict-not-taken design with a 2-cycle branch penalty resolved in EX (since a misprediction only needs to flush IF/ID and ID/EX), the `flush` input is retained here for completeness/uniformity across all pipeline registers, and to safely support a reset-like clearing if ever needed for debug or future hazard scenarios.

```verilog
alu_result_out    <= 32'b0;
mem_read_data_out <= 32'b0;
rd_out            <= 5'b0;
pc_plus4_out      <= 32'b0;
Jump_out          <= 1'b0;
RegWrite_out      <= 1'b0;
MemToReg_out      <= 1'b0;
```

## 6. Priority

When multiple control conditions occur simultaneously, the following priority shall be used:

1. Reset
2. Flush
3. Normal Update

```verilog
always @(posedge clk)
begin
    if (reset)
    begin
        ...
    end
    else if (flush)
    begin
        ...
    end
    else
    begin
        ...
    end
end
```

## 7. Hardware Resources

This module consists only of pipeline registers. No combinational logic, arithmetic, logical, or memory operation is performed inside this module. It simply delays the Memory stage outputs by one clock cycle before forwarding them to the Write-Back stage.

Stored signals:

- ALU result
- Data Memory read data
- Destination register (rd)
- PC+4 (JAL return address)
- Control signals:
  - Jump
  - RegWrite
  - MemToReg

## 8. Reset Behavior

Active-high synchronous reset.

After reset:

- ALU result = 0
- Memory read data = 0
- Destination register = 0
- PC+4 = 0
- Jump = 0
- RegWrite = 0
- MemToReg = 0

The Write-Back stage receives a NOP — no register write occurs.

## 9. Verification Strategy

The module should be verified using a dedicated testbench covering:

- Reset operation
- Normal pipeline update
- ALU result transfer
- Memory read data transfer
- Destination register transfer
- PC+4 transfer (verify JAL return address propagation reaches this final stage correctly)
- Control signal transfer
- Flush operation
- Multiple consecutive instruction transfers
- Back-to-back instruction transfers without data corruption
- End-to-end check: confirm `MemToReg`/`Jump` combination correctly identifies which of the three write-back sources (ALU result, memory data, PC+4) should ultimately reach the Register File

| Test Case | Expected Result |
|-----------|-----------------|
| Normal clock | Inputs appear at outputs |
| Reset | All outputs become zero |
| Flush | All outputs become zero |
| LW instruction | mem_read_data correctly transferred, MemToReg=1 |
| JAL instruction | PC+4 and Jump correctly transferred |
| R-type/I-type instruction | alu_result correctly transferred, MemToReg=0, Jump=0 |
| Multiple instructions | Correct sequential transfer |
| Consecutive instructions | No corruption between adjacent instructions |

## 10. Notes

- This module forms the pipeline boundary between the **Memory Access (MEM)** and **Write-Back (WB)** stages — the last pipeline register in the datapath.
- It delays all required data and control signals by one clock cycle.
- No ALU operation, memory access, or other combinational logic occurs inside this module.
- The actual write-back multiplexing (Mux A: `MemToReg` selecting `mem_read_data_out` vs. `alu_result_out`; Mux B: `Jump` overriding with `pc_plus4_out`) happens in the WB stage, *after* this register — not inside it. This module's job is purely to carry the three candidate values (`alu_result`, `mem_read_data`, `pc_plus4`) and their selecting control signals (`MemToReg`, `Jump`) forward intact.
- No dedicated `MemRead` signal exists in this design (see `EX_MEM` spec notes) — not needed here either, since `mem_read_data_in` is always valid combinationally from `DataMemory` regardless of instruction type, and `MemToReg` alone determines whether it's actually used.
- `RegWrite_out` ultimately gates whether the Register File accepts the write-back value at all — for instructions with `RegWrite=0` (SW, branches), the write-back value computed here is irrelevant, consistent with earlier don't-care markings in the single-cycle design.
