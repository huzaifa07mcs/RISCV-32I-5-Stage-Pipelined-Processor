# ALU Specification

## 1. Module Name
ALU

## 2. Purpose
The Arithmetic Logic Unit performs all arithmetic and logic operations required by the RV32I subset — addition, subtraction, bitwise AND/OR/XOR, and signed less-than comparison. It is also reused for effective address calculation (LW/SW, via ADD) and branch comparison (BEQ/BNE, via SUB + Zero flag). The operation performed is selected by a control signal (`ALUControl`) generated by the ALU Control unit.

## 3. Inputs

| Signal | Width | Description |
|---|---|---|
| operand_A | 32-bit | First ALU operand (typically rs1 value) |
| operand_B | 32-bit | Second ALU operand (rs2 value or sign-extended immediate, selected by mux before reaching ALU) |
| ALUControl | 3-bit | Selects the operation to perform |

## 4. Outputs

| Signal | Width | Description |
|---|---|---|
| ALU_result | 32-bit | Result of the selected operation |
| Zero | 1-bit | Set to 1 when ALU_result == 0 (used for BEQ/BNE branch decision) |

## 5. Parameters

| Parameter | Value | Description |
|---|---|---|
| XLEN | 32 | Processor data width |

## 6. Internal Storage
Not applicable — ALU is purely combinational logic, no storage elements.

## 7. Initialization
Not applicable — no memory or registers to initialize.

## 8. Functional Behavior

**ALUControl encoding:**

| ALUControl | Operation | Used By |
|---|---|---|
| 3'b000 | ADD | ADD, ADDI, LW (address calc), SW (address calc) |
| 3'b001 | SUB | SUB, BEQ, BNE (comparison via subtraction) |
| 3'b010 | AND | AND |
| 3'b011 | OR | OR |
| 3'b100 | XOR | XOR |
| 3'b101 | SLT | SLT (signed less-than) |
| others | Reserved / default = 0 | — |

**Operation (combinational):**
```verilog
case (ALUControl)
    3'b000: ALU_result = operand_A + operand_B;
    3'b001: ALU_result = operand_A - operand_B;
    3'b010: ALU_result = operand_A & operand_B;
    3'b011: ALU_result = operand_A | operand_B;
    3'b100: ALU_result = operand_A ^ operand_B;
    3'b101: ALU_result = ($signed(operand_A) < $signed(operand_B)) ? 32'd1 : 32'd0;
    default: ALU_result = 32'b0;
endcase

Zero = (ALU_result == 32'b0) ? 1'b1 : 1'b0;
```

`Zero` is derived combinationally from `ALU_result` regardless of which operation is selected, but is only meaningful to the Control/Datapath logic when `ALUControl = SUB` (used for BEQ: branch taken when Zero=1; BNE: branch taken when Zero=0).

SLT uses `$signed()` casting to ensure two's complement signed comparison — without this, Verilog would perform unsigned comparison and give incorrect results for negative operands.

## 9. Reset Behavior
ALU has no reset. It is a purely combinational module — output updates immediately whenever `operand_A`, `operand_B`, or `ALUControl` changes, with no dependency on clock or reset.

## 10. Verification
The following test cases shall be verified:
- ADD: positive + positive (e.g., 5 + 3 = 8)
- ADD: positive + negative, confirm correct two's complement result
- SUB: result positive, negative, and exactly zero (to check Zero flag)
- SUB with equal operands — confirm Zero = 1 (validates BEQ path)
- SUB with unequal operands — confirm Zero = 0 (validates BNE path)
- AND: verify bitwise AND on a mixed bit pattern
- OR: verify bitwise OR on a mixed bit pattern
- XOR: verify bitwise XOR on a mixed bit pattern
- SLT: operand_A < operand_B (both positive) — result = 1
- SLT: operand_A > operand_B (both positive) — result = 0
- SLT: operand_A negative, operand_B positive — confirm signed comparison gives correct result (result = 1)
- SLT: both operands negative — confirm signed comparison correctness
- Invalid/undefined ALUControl — confirm default case gives ALU_result = 0

## 11. Notes
- Purely combinational — required for single-cycle timing, ALU result must be available within the same cycle for MEM/WB stage use.
- `Zero` flag is a byproduct output always computed, but only consumed meaningfully during SUB (branch instructions) — Control Unit decides whether to act on it based on instruction type.
- ALUControl is generated by a separate **ALU Control** module (upcoming), which decodes it from the instruction's `funct3`/`funct7` fields combined with a higher-level `ALUOp` signal from the Main Control Unit — this keeps ALU itself decoupled from instruction encoding details.
- Reused without modification in the pipelined processor — sits in the EX stage.
